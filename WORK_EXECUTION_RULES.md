# WORK EXECUTION RULES

You are implementing an already-designed project.

You are not the product architect.

The frozen documents in this repository are authoritative.

## First Authorized Work Run

Only PHASE 1 is authorized.

Implement the Repository A skeleton and deterministic core.

Do not enter PHASE 2 automatically.

## Absolute Rules

Do not:
- rename the core Primitive
- replace the product concept
- add token economics
- add payments or escrow
- add another blockchain
- add a backend or database
- add authentication/profile systems
- add appeals/revisions/reputation
- broaden artifact formats
- change consensus semantics
- replace independent Validator re-derivation with Leader-output checking
- use strict equality of free-form LLM text as core equivalence
- convert model/system errors into UNKNOWN
- deploy
- send transactions
- create Repository B
- move to the next phase without explicit authorization

## Allowed Adaptations

You may adapt only when needed for the current installed/stable GenLayer environment:
- SDK/import syntax
- GenVM storage syntax
- supported test harness syntax
- exact helper/API names

Record any adaptation in the phase checkpoint.

Semantic changes are not allowed.

## Work Discipline

inspect
→ implement
→ test
→ fix
→ re-test
→ write checkpoint
→ STOP

Avoid speculative refactors.

Do not optimize passing code without a concrete reason.

Keep context focused on the current phase.
